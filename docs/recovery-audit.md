## Journal and authorization findings

Sprint 6 checked user_version and selected the last event. An item with missing events vanished from pending recovery. An impossible transition could be interpreted as authority to restore. Recorded paths and sizes could disagree with the fixed fixture slots without detection. On opening the separate operations database the fixture now validates SQLite integrity, foreign keys, required item invariants and the ordered event history before using the journal. Pre-intent reconciliation previously declared interruption without checking the slots. It now verifies the intact source and empty vault, or records ambiguity. Unknown versions, corruption and inconsistent evidence stop recovery. SQLite FULL synchronization, metadata checks and a valid transition history cannot authenticate a hostile same-user database rewrite, detect every valid-prefix truncation or distinguish a reused inode after restart.

Review time is monotonic and authorization is consumed in memory. The current TTL check precedes validation and the intent commit; there is no bound on subsequent I/O latency. A plan can become stale while I/O stalls. Protection is a current Boolean; an intervening enable/disable cycle leaves no policy epoch. A file descriptor pins the inode, but leaves its contents writable and its name replaceable. Linux renameat2 chooses the source by name at movement. Open parent descriptors survive relocation, including relocation outside the reviewed project. The advisory instance lock only coordinates cooperating clients. These are production blockers.

Rejecting all Git markers in an owned fixture avoids the live-index problem. A new scan generation and fresh index check cannot freeze tracked status, untracked edits, worktree membership or preferences across a rename. Future qualification needs an enforceable ownership or quiescence protocol for the complete operation lifetime. Restart must invalidate all outstanding consent.

## Process interruption

The Linux test runner starts a new process for each direction and checkpoint. Each worker creates a fresh temporary fixture and delivers SIGKILL to itself before intent, after intent immediately before rename, after rename before directory synchronization, or after directory synchronization before completion. The surviving test process independently opens the database, acquires the instance lock and examines both slots. Tests verify exact bytes, inode, expected state and absence of automatic retries. A crash before restore intent leaves a verified quarantined item. Simulation-only tests remain for failed transactions and conflicting slots. These tests retain kernel caches; power loss, device flush behavior and hostile writers are unqualified.

## Windows qualification scope

CreateFileW semantics are exercised through Rust OpenOptionsExt with explicit desired access, FILE_SHARE_READ, FILE_FLAG_OPEN_REPARSE_POINT and FILE_FLAG_BACKUP_SEMANTICS. An incompatible existing writer prevents acquisition. Successful acquisition restricts subsequent incompatible write/delete opens while the handle lives. Metadata queries use GetFileInformationByHandleEx with FileIdInfo, FileAttributeTagInfo and FileStandardInfo. Compare volume and 128-bit ID; reject reparse objects and multiply linked files. The tests retain source and destination directory handles inside their private fixture. SetFileInformationByHandle with FileRenameInfo addresses the source by handle and disables replacement. The destination is an absolute fixture path, still resolved through the namespace. Only the test primitive moves synthetic bytes. No journal-backed Windows executor is authorized.

Hosted qualification requires NTFS. Cases cover ordinary handle contention, parent rename attempts, a destination created by another thread, pre-existing writers, single-volume identity, junction rejection and round-trip content preservation. Symlink creation depends on privilege. The case probe checks the directory case mode and exercises case-variant destination collisions in the default mode and a competing case-only source rename. Case-sensitive directory qualification, writable mappings, volume mount points, cross-volume moves, ACL permutations, arbitrary ancestor relocation, remote filesystems, namespace aliases outside the private root and durable directory entry flush ordering lack qualification. A held handle alone cannot establish these guarantees. Reject real movement on every platform.

## Scanner boundary and next qualification gate

The Linux design probe compares opened directory ancestry to a retained vault identity, including explicit nested roots, an alias through an intermediate link, and a renamed vault with a new directory at the old name. Production discovery has no vault registry. A bind mount exposing only a descendant can omit the vault root from visible ancestry. Case and name comparisons, symlink checks and ordinary device numbers do not establish membership across mounts. Require a trusted registry and mount/alias policy for each supported filesystem, or refuse affected scans and operations.

Before considering production cleanup, independently qualify namespace and writer exclusion, persistent identity after process and machine restart, journal authenticity and destination durability on disposable Windows volumes. Require an external reviewer and maintainer sign-off on the exact platform, API and artifact class.
